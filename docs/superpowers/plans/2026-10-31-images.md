# Images (Nano Banana) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jillian makes social-post images and family cards inside the assistant (Google's Nano Banana), optionally from her own photos, and downloads them to post or finish in Canva.

**Architecture:** The Worker calls the Gemini API (`generateContent`) with a prompt it builds itself from the saved post or trip, Jillian's direction and `brains/images.md`, plus up to 3 of her photos. Image bytes live in a new R2 bucket and the facts about each image in a new D1 table, owned by a saved draft or a trip. Deleting the draft or trip deletes its images.

**Tech Stack:** Cloudflare Workers, R2 (`IMAGES` binding), D1, the Gemini REST API with `fetch` (no SDK), React, and Vitest.

**Spec:** No separate spec doc. Michael opted out of more questions ("do whatever else you think we need to do") after choosing Nano Banana in the website plus downloads for Canva on 10/31. The design calls below are mine and are listed for him in the hand-off.

## Design calls (mine)
- **Model:** `gemini-nano-banana-2.1` at 1K, about $0.034 per image. Its id lives in one constant, `IMAGE_MODEL` in `worker/gemini.ts`.
- **Where it appears:** the **Images** section under a finished Spread the Magic post (it needs a saved draft), and **Cards for the family** on a trip's page (countdown, birthday, welcome home, bon voyage).
- **The prompt is built on the server.** It uses the post's client text without the notes, or the trip's title, destination, dates and party, plus her direction and the rules in `brains/images.md`. The browser sends only ids, a shape and her direction.
- **Shapes:** Square 1:1, Portrait 4:5, Story 9:16, Wide 16:9.
  - Facebook and Instagram posts default to Portrait.
  - Newsletters and website promos default to Wide.
  - Cards default to Portrait.
- **Photos:** the browser shrinks each photo to at most 1600 px on its long side, as JPEG. Each upload is at most 5 MB. Up to 3 photos go into one image. "Change this one" sends the earlier image back with her new direction.
- **Safety:**
  - Her direction goes through the same guard as everything else: card, SSN and passport numbers are blocked; emails and phone numbers are masked.
  - The rules forbid characters, castles and logos.
  - At most 100 new images across the site in any 24 hours (about $3.40 a day) protects the shared password from runaway cost.
- **Errors Jillian sees:**
  - No key: "Images aren't connected yet (Google API key)."
  - Billing not set up: "Images need billing turned on in Google AI Studio."
  - Blocked by Google: "Google wouldn't make that one — try describing it differently (no characters or logos)."
  - Busy: "It's busy right now — try again in a minute."
  - Anything else: "No image came back — try again."
- **Canva:** **Download** saves a PNG. The panel says to drag it into Canva to finish.

## Global Constraints
- The secret is `GEMINI_API_KEY`. Michael adds it himself (`.dev.vars` and `wrangler secret put`), and code must never log it.
- The R2 bucket is `magical-assistant-images`, binding `IMAGES`.
- The D1 migration is `migrations/0003_images.sql`. Apply it remotely BEFORE pushing, because pushes auto-deploy.
- Images are served only behind the session cookie, with `cache-control: private, max-age=31536000, immutable`.
- Error responses and logs never echo Jillian's text or Google's error message.
- All Claude tools stay on `claude-opus-5-5`. This feature adds no Claude calls.

## Review Focus
- An uploaded file that isn't really an image (renamed PDF, HEIC that Chrome can't read). The server rejects anything whose first bytes aren't JPEG, PNG or WebP, and the browser says "Couldn't read that photo — try a JPEG or PNG." (Task 2 test.)
- A photo or earlier image id that belongs to a different draft or trip gets 400, never another family's photo. (Task 2 test.)
- Deleting a post or trip leaves no orphaned images in R2. (Task 3 test.)
- Google answers 200 with no image (a blocked prompt). She gets the "wouldn't make that one" message, and nothing is saved or counted. (Task 1 and Task 2 tests.)
- Clicking "Make an image" twice quickly: the button is disabled while working, and the daily cap still holds on the server. (Task 4 by hand; Task 2 cap test.)

### Task 1: Gemini client and shared image types

**Files:**
- Create: `shared/images.ts`, `worker/gemini.ts`, `brains/images.md`
- Modify: `worker/brains.ts` (add `images`)
- Test: `tests/gemini.test.ts`

**Interfaces:**
- Produces, in `shared/images.ts`:
  - `type Shape = "square" | "portrait" | "story" | "wide"`
  - `SHAPES: Record<Shape, { label: string; aspect: string }>`
  - `defaultShape(channel?: string): Shape`
  - `type CardKind = "countdown" | "birthday" | "welcome-home" | "bon-voyage"` and `CARD_KINDS: Record<CardKind, string>` (labels)
  - `type ImageOwner = { type: "draft" | "trip"; id: string }`
  - `interface ImageMeta { id; kind: "upload" | "generated"; shape: Shape | null; prompt: string; created_at: number }`
  - Limits: `MAX_PHOTO_BYTES = 5_000_000`, `MAX_DIRECTION = 1_000`, `MAX_REFERENCE_PHOTOS = 3`, `DAILY_IMAGE_LIMIT = 100`, `IMAGE_COST_USD = 0.0336`.
- Produces, in `worker/gemini.ts`:
  - `IMAGE_MODEL`
  - `interface ImageClient { generate(r: { prompt: string; images: InlineImage[]; aspect: string }): Promise<InlineImage> }`, where `InlineImage = { mimeType: string; data: Uint8Array }`
  - `defaultImageClient(env, fetchImpl = fetch): ImageClient`
  - `class ImageError extends Error { kind: "no-key" | "billing" | "blocked" | "busy" | "failed" }`
  - `toBase64` and `fromBase64`

- [ ] **Step 1: Write the failing tests**
  - `defaultShape("Instagram caption") === "portrait"`, `defaultShape("Website promo") === "wide"`, `defaultShape() === "portrait"`.
  - `fromBase64(toBase64(bytes))` round-trips 300 KB of random bytes.
  - The client POSTs to `https://generativelanguage.googleapis.com/v1beta/models/gemini-nano-banana-2.1:generateContent`.
    - Header: `x-goog-api-key: <key>`.
    - Body: `{contents:[{role:"user",parts:[{text},{inlineData:{mimeType,data}}…]}], generationConfig:{responseModalities:["IMAGE"], imageConfig:{aspectRatio:"4:5", imageSize:"1K"}}}`.
    - It returns the decoded bytes of the first `inlineData` part (it also accepts `inline_data`).
  - An empty key throws `ImageError` with kind `no-key`, and `fetch` is not called.
  - Errors map to kinds:
    - `promptFeedback.blockReason: "SAFETY"`, or `finishReason` in `IMAGE_SAFETY`, `IMAGE_PROHIBITED_CONTENT`, `PROHIBITED_CONTENT` or `SAFETY` → `blocked`;
    - HTTP 429 → `busy`;
    - HTTP 400 or 403 whose body mentions billing → `billing`;
    - HTTP 400 or 403 whose body mentions API key → `no-key`;
    - anything else → `failed`.
- [ ] **Step 2:** `npx vitest run tests/gemini.test.ts` fails (module missing).
- [ ] **Step 3: Implement.**
  - Base64 goes through `btoa`/`atob` in 32 KB chunks (no `Buffer` in Workers).
  - Write `brains/images.md`, the rules for every image:
    - no Disney, Universal, Marvel, Pixar or Star Wars characters or look-alikes;
    - no castles, park icons, logos or mouse-ear shapes;
    - text only if asked, spelled exactly, with no prices, dates or discounts she didn't give;
    - real people in her photos keep their faces, ages and bodies, and nobody is added unless asked;
    - no client names on post images;
    - warm, bright, family-friendly style;
    - brand colors: a TODO for Jillian's brand guide.

### Task 2: Storage and the /api/images routes

**Files:**
- Create: `migrations/0003_images.sql`, `worker/images.ts`, `tests/helpers/fakeR2.ts`
- Modify: `worker/store.ts` (image queries), `worker/index.ts` (route `images`), `wrangler.jsonc` (`r2_buckets`), `worker-configuration.d.ts` (via `npm run cf-typegen`), `.dev.vars.example`
- Test: `tests/images.test.ts`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `handleImages(request, env, segments, deps: { now?: () => number; makeImageClient?: (env: Env) => ImageClient } = {})`
  - `deleteImagesOf(env, owner: ImageOwner, remove: () => Promise<unknown>): Promise<void>`. It collects the owner's R2 keys, runs `remove()`, which deletes the parent row (the image rows cascade), then deletes the keys from R2.
  - The routes:
    - `GET /api/images?owner=draft:<id>` or `trip:<id>` → `ImageMeta[]`, newest first;
    - `POST /api/images` (multipart: `owner`, `file`) → 201 `ImageMeta`;
    - `POST /api/images/generate` with `{owner, direction, shape, photoIds?, baseImageId?, card?}` → 201 `ImageMeta`;
    - `GET /api/images/:id` → the bytes;
    - `DELETE /api/images/:id` → `{ok:true}`.
- Table `images`:
  - columns `id`, `draft_id` (FK drafts ON DELETE CASCADE), `conversation_id` (FK conversations ON DELETE CASCADE), `kind` (upload or generated), `mime`, `bytes`, `shape`, `prompt`, `model`, `cost_usd`, `created_at`;
  - CHECK that exactly one owner is set;
  - indexes on each owner with `created_at DESC`, and on `(kind, created_at)`.
- R2 key: `images/<id>`.

- [ ] **Step 1: Write the failing tests**, with a `fakeR2()` (a Map with `put`, `get`, and `delete` of one key or an array) and a fake `ImageClient` that records calls.
  - An upload of JPEG bytes to a Spread the Magic draft lists as `kind: "upload"`, and its bytes are in R2.
  - Uploads are rejected:
    - non-image bytes or a file over `MAX_PHOTO_BYTES` → 400;
    - a missing draft → 404;
    - a draft from another tool, or a chat (only trips) → 400.
  - Generating for a post:
    - the prompt includes the post text but not the "For Jillian only" notes, her direction, and a line of `brains/images.md`;
    - aspect is `"4:5"` for an Instagram post;
    - the chosen photos are passed in order;
    - the result is saved with `kind: "generated"` and `cost_usd` 0.0336.
  - Generating a card for a trip: the prompt names the card kind, the trip title, destination and dates.
  - A direction with a card number → 400 with the guard's message, and no client call. An email in the direction is masked in both the prompt and the saved `prompt`.
  - Ids that break the rules → 400 with no client call:
    - a photo id from another owner;
    - 4 photo ids;
    - a `baseImageId` that is an upload.
  - Editing: `baseImageId` puts that image first, and the prompt asks to change it.
  - Client errors become 503 or 429 with the exact messages above (`blocked` → 422). Nothing is saved.
  - Once 100 generated images exist in the last 24 hours → 429 "That's 100 images today — try again tomorrow."
  - `GET /:id` returns the bytes with the right `content-type` and the private immutable cache header; an unknown id → 404.
  - `DELETE /:id` removes the row and the R2 object.
- [ ] **Step 2:** the tests fail.
- [ ] **Step 3: Implement** the migration, the store functions (`addImage`, `listImages`, `getImage`, `deleteImage`, `imageIdsOf`, `countGeneratedSince`), `worker/images.ts`, the route, the binding, and the typegen.
  - Check the image type from its first bytes: `FF D8 FF` for JPEG, `89 50 4E 47` for PNG, `RIFF....WEBP` for WebP.
  - Log failures as `describeError`-style names only.
